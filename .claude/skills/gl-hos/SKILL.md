# โปรแกรม GL ของโรงพยาบาล (GL_HOS .accdb)

ศึกษาจากไฟล์ GL_HOS_70 (ปีงบ 2570 = 1 ต.ค. 2569–30 ก.ย. 2570) ข้อมูลถึง 6 พ.ย. 2569 ตรวจ 25 พ.ย. 2569 ระดับความเชื่อมั่น: **[ไฟล์]** = อ่านจากข้อมูลจริงในไฟล์, **[เทียบ]** = เทียบกับ insight ด้วย db-cli, **[อนุมาน]** = ยังต้องถามการเงิน

schema เต็ม, saved query ที่เกี่ยวข้อง และผลเทียบเป็นตัวเลขอยู่ใน `references/schema.md`

## 1. อ่านไฟล์อย่างปลอดภัย

- คัดลอกไฟล์ไปที่ scratchpad ก่อนเสมอ อ่านจากสำเนา ห้ามเปิดด้วย Access หรือ COM (`Access.Application`) เพราะ macro/VBA รันเองได้
- อ่านด้วย OLE DB: PowerShell `System.Data.OleDb` provider `Microsoft.ACE.OLEDB.16.0` (หรือ 12.0) connection string มี `Mode=Read` ใช้ `GetOleDbSchemaTable` (Tables/Columns/Primary_Keys/Foreign_Keys/Views/Procedures) ได้ทั้งรายการตาราง คอลัมน์ ความสัมพันธ์ และ SQL ของ saved query ; อ่านแค่ SELECT
- อ่านไม่ได้ผ่าน OLE DB: `MSysObjects` (no read permission จึงไม่เห็น linked table), form, report, VBA, macro (ฟังก์ชันใน query เช่น `getFD()`, `NetToDr()`, `GetGFType()` อยู่ใน VBA)
- `LIKE` ผ่าน OLE DB ใช้ `%`/`_` ไม่ใช่ `*` ; คำว่า `note`/`lines` ใช้เป็น alias ไม่ได้ (reserved)
- ข้อมูลบุคคลในไฟล์: `SetTbl` (ชื่อผู้บริหาร/ผู้ทำบัญชี), `Vertbl` (ชื่อผู้เขียนโปรแกรม), `DataTbl.Note` (ข้อความอิสระ อาจมีชื่อผู้ขาย/บุคคล), ชื่อบัญชีเงินฝากมีเลขบัญชีธนาคาร ห้ามคัดลอกค่าเหล่านี้ ; ไม่พบตารางผู้ใช้/รหัสผ่าน

## 2. โครงสร้าง [ไฟล์]

โปรแกรม "HOS Previous > 2013+" เมนู 5 ขั้น: ตั้งค่าเริ่มต้น (`SetTbl`) → ผังบัญชีย่อยสุด → ชื่อบัญชีหลักในงบ (`AccID1`) → ลงข้อมูล (form `DataTbl`) → รายงาน (form `Form1`)

- **ใบสำคัญ** = `DataTbl` (header, PK `ID` autonumber) + `DataTbl1` (บรรทัด, FK `ID`) ; `DataTbl2` เป็นแบบแบน header+บรรทัดในแถวเดียว (ว่าง) รวมกันใน query `UnionData` ที่รายงานทุกตัวอ่าน
  - `DataTbl`: `AccDate` วันที่บัญชี, `DataDate` วันที่คีย์, `DocID` เลขที่เอกสาร (ข้อความ), `BookID` → `BookTbl`, `BudgetType` → `BudgetTypeTbl`, `Note` คำอธิบาย, `ApAr` รายการย่อย/บัญชีย่อยลูกหนี้-เจ้าหนี้ → `SubLedTbl` (ไม่ได้ใช้ ว่างทุกแถว), `OrgID1` หน่วยงาน (`00` = รพ. เอง), `ChargeID`/`ChargeDate`/`RefID` (ว่าง), `IsClosing`, `ToBe0`, `NotGF3`
  - `DataTbl1`: `AccCode1` → `ChartOfAccounts.AccCode`, `Dr`, `Cr` (Currency 4 ตำแหน่ง), `RefID1` อ้างอิงบรรทัด (ข้อความ 50), `RefDate` (ว่าง), `InterTransac`, `RunID1`/`RunID2` ลำดับบรรทัด
  - บรรทัดหนึ่งมี Dr หรือ Cr ฝั่งเดียว บัญชีเดียวกันซ้ำได้หลายบรรทัดในใบเดียว ; โปรแกรม**ไม่บังคับ Dr = Cr** (พบใบที่ยังไม่สมดุล 4 ใบ มี query `NCheckDrCr` ไว้ตรวจ) ไฟล์ที่เราส่งต้องสมดุลเอง
- **สมุดรายวัน** (`BookTbl`): 1 เงินรับ (ร.), 2 เงินจ่าย (จ.), 3 ขาย (ข.), 4 ซื้อ (ซ.), 5 ทั่วไป (ท.) ; เลขที่เอกสาร `รร.<n>/70` (รับ), `รจ.<n>/70` (จ่าย), `รท.<n>/70` ตามปีงบ 2 หลัก ; สมุดขาย/ซื้อไม่มีเลขที่เอกสาร
- **ประเภทเงิน** (`BudgetTypeTbl`): 1 เงินงบประมาณ (ไม่ส่ง GF), 4 เงินบำรุง (รายการลูกหนี้ทั้งหมด), 9 ประกันสังคม, 10 สวัสดิการ, 11 อื่นๆ, 12 บัญชี๕, 13 บัญชี๗
- **ยอดยกมา**: ใบ `ID` 1 (เงินบำรุง) และ 2 (งบประมาณ) ลงวันที่ 30 ก.ย. ของปีก่อน `SetTbl.StartDate` ; ช่วงรายงานคือ `SetTbl.FDate`/`TDate` ปีงบ `FYear` เป็นเลขไทย
- **ผังบัญชี** `ChartOfAccounts` (928 รหัส): รหัส `##########.###` (10.3) เหมือนของเรา มีรหัสย่อย 5 หลัก `.xxx01` "ภายในกรมเดียวกัน (Manual)" เพิ่มปี 2569 (เช่น .20301, .50601) ; `MinorID` บัญชีคุม (`AccID1`) → หมวดในงบ (`AccIDTbl`) ; `GFId` = 10 หลักแรก (รหัส GFMIS, ตาราง `GF`/`GFAndGL`) ; `Trading` รหัสคู่ค้า GFMIS (80074 สปสช., 80066 สปส., 03004 กรมบัญชีกลาง, 21002 แรงงานต่างด้าว) ; `UseOrNot` Use/No ; `NotGF1` ไม่ส่ง GF
- ไม่มีบัญชีย่อยรายราย (VN/AN/HN) ในใบสำคัญ GL เก็บแค่ยอด

## 3. บัญชีลูกหนี้ของเราใน GL [ไฟล์]

ทุกรหัสใน `ar_account` (code/revenue/diff/clear) และ `ar_transfer.account_code` ของเรามีใน `ChartOfAccounts` ครบ 166/166 รหัส (ตรวจ 25 พ.ย. 2569) ; ที่ GL ตั้ง `UseOrNot = No`: 1102050101.223/.224, 1102050194.115/.116, 4301020105.267/.268/.269 ข้อต่าง:

- **การเงินใช้รหัส Manual แทนรหัสหลักบางตัว**: UC OP นอก CUP ในจังหวัด สธ. ลง **1102050101.20301** / รายได้ 4301020105.20301 (ไม่ใช่ .203) ; ยกมามี .50601, .70201, .70401 ; `ar_account` ของเรามีรหัสเหล่านี้แล้ว แต่กติกาบัญชี (`ar_account_rule`) ยังลง .203 ต้องตกลงกับการเงินว่าจะแก้กติกาหรือแปลงตอนส่งออก
- เงินฝากธนาคารแยกหลายบัญชีย่อย เงินโอนจาก สปสช. เข้า 1101030102.10105 ("รับโอน UC") ส่วนเงินสดห้องเก็บเงิน 1101010101.101 ; ของเราไม่ระบุรหัสเงินฝาก (`CASH_NAME` code null ใน `journal.ts`)

## 4. การเงินลงลูกหนี้ใน GL อย่างไร (ต.ค. 2569) [ไฟล์]

1. **ตั้งหนี้รายวัน = สมุดขาย (BookID 3)** หนึ่งใบต่อวัน (31 ใบ ต.ค.) `Note` "บันทึกบัญชีลูกหนี้ค่ารักษาพยาบาลประจำวัน" ไม่มี DocID/RefID คีย์รวดเดียววันที่ 7 พ.ย. (`DataDate`) = นำเข้ายอดจากโปรแกรม Claim หลังสิ้นเดือน [อนุมาน] ; บรรทัดละบัญชีต่อวัน:
   - Dr ลูกหนี้ = **ยอดสุทธิหลังเพดาน/สัดส่วน** (ค่ารักษา − ส่วนต่าง)
   - Cr รายได้คู่ = ค่ารักษาเต็ม
   - Dr บัญชีส่วนต่าง (4301020105.239 แยกบรรทัดต่อบัญชีลูกหนี้, 4301020106.315/.317 ประกันสังคม)
   - มีบรรทัดยอด 0 ติดมาจากแม่แบบ (query `DelDataTbl100` ลบบรรทัด 0/0)
   - IP ลง .202 และแยก CR เป็น .217 แล้ว (ของเรายังรวมใน .202)
2. **ปรับปรุงสิ้นเดือน = สมุดทั่วไป (BookID 5)** ใบเดียววันสิ้นเดือน "ปรับปรุงบัญชีลูกหนี้ตามนโยบายบัญชีสิ้นเดือน": Cr .201 ทั้งเดือน / Dr .214 = เงินโอนเหมาจ่ายที่รับในเดือน / Dr .229 ส่วนที่เหลือ ; Cr .209 / Dr .217 ; Cr .701 / Dr 4301020106.711 ; Cr .501 / Dr 2103010103.502 (+ โอนระหว่างบัญชีเงินฝาก) = ตรงกับกติกา `/fund/ar-capitation` และ fwf ของเรา
3. **รับเงิน = สมุดเงินรับ (BookID 1)** ใบละวันโอน "รับเงินโอนค่าบริการทางการแพทย์ - สปสช." หลายสิบบรรทัด: Dr เงินฝาก `RefID1` = เลขอ้างอิงธนาคาร/ลำดับ (`<เลข>/<ลำดับ>`) ตามด้วย Cr ลูกหนี้/รายได้ที่ `RefID1` = งวด STM (`YYMM_OP_NN`, `YYMM_OP_NN_อุทธรณ์`), เลขที่ REP/หนังสือ (9 หลัก) หรือชื่อโครงการ ; ส่วนต่างของหนี้ปีก่อนลง 3102010102.102 (ผลสะสมจากการแก้ไขข้อผิดพลาด-รายได้) ; เงินงบปีก่อนลง 3102010102.201 (บางรายการการเงินลง .214)

## 5. ผลเทียบกับสมุดเรา (ต.ค. 2569) [เทียบ]

ตั้งหนี้ OP รายวัน**ตรงกันเกือบทั้งหมด** จึงใช้ `ar_ledger` ส่ง GL ได้: 5 ต.ค. ตรงถึงสตางค์ทุกบัญชียกเว้น .201 (GL 542,173.52 / เรา 560,421.52), .209 (ต่าง 50), .301 (ส่วนต่างปัดต่าง 0.01), .202 (เรามากกว่า 500 = .217 ของ GL) ; ทั้งเดือนตรงถึงสตางค์: .401, .308, .701, 1102050102.108/.110/.801/.803 ; ต่าง < 1%: .201 (−79,544.90), .203 (สุทธิ 40,487.75 vs 40,512.75), .209, .216, .301, .307 ; ต่างมาก: IP (.202 เรา 4.67 ล้าน vs 5.00 ล้าน, .302, .402, .802, 1102050102.107/.106) น่าจะเพราะวันที่ตั้งหนี้ IP คนละเกณฑ์ (เรา dchdate) [อนุมาน]

รับชำระ/ตัดหนี้ยังเทียบไม่ได้: STM ที่เราลงต้นเดือน ต.ค. (.202 settle+diff 20.1 ล้าน ของหนี้ปีงบ 2569) ไม่มีใน GL ต.ค. (.202 ยกมา 5.1 ล้าน) ; เงินโอน .214 เรา 7,224,700 GL 7,228,191 (3,491 "OP ANYWHERE ปี 69" เราลง 3102010102.201) ; พ.ย. 2569 ใน GL ยังไม่มีสมุดขาย (ข้อมูลถึง 6 พ.ย.) จึงยังเทียบไม่ได้

## 6. ช่องทางนำเข้าในโปรแกรม [ไฟล์]

ไม่มีตาราง staging สำหรับใบสำคัญทั้งใบ ทุกทางเติม**บรรทัดเข้าใบที่เปิดอยู่ใน form** (`forms!DataTbl!ID`) ผู้ใช้ต้องสร้าง header เอง:
- `AppImportData`: `ImportData(Code, Dr, Cr)` → `DataTbl1` (ตาราง ImportData ไม่อยู่ในไฟล์ สร้างตอนนำเข้า น่าจะจาก Excel [อนุมาน])
- `qryForAddData1`: `TB1(ID, acccode1, accname1, dr1, cr1)` → `DataTbl1` (ตารางมีอยู่ ว่าง)
- import spec ข้อความความกว้างคงที่: รหัสบัญชี ตำแหน่ง 1–15, ชื่อบัญชี 16–88, เดบิต/เครดิต/สุทธิต่อท้าย (ใช้รวมงบทดลองหน่วยงาน)
- ส่งออกงบทดลองไป GL MOPH/รวมเครือข่าย: query `งบหน่วยงานส่งออก` (รหัสบัญชี, ชื่อ, ยอดยกมา, เดบิต, เครดิต, ยอดยกไป), `AppOrg*`/`AppSub*` เขียนลงไฟล์ mdb ภายนอก

## 7. แนวทางส่งข้อมูลจากระบบเรา (ข้อเสนอ ยังไม่ทำ)

ระดับรายละเอียด: **ยอดรวมต่อบัญชีต่อวันต่อสมุด** ไม่ส่งรายราย ไฟล์ Excel/CSV คอลัมน์ `Code, Dr, Cr` (ตรง ImportData) หนึ่งชุดต่อใบสำคัญ พร้อมหัว (วันที่, สมุด, ประเภทเงิน 4, คำอธิบาย) ให้ผู้ใช้สร้างใบแล้วนำเข้า ; ต้องสมดุลทุกใบ

| ar_ledger | ใบใน GL | บรรทัด |
|---|---|---|
| set/adjust/cancel/reverse + diff ของ source หนี้ (rcpt_debt, ipt) | สมุดขาย ใบละ `entry_date` | Dr ลูกหนี้ = ผลรวม charge + diff ; Cr `revenue_code` = ผลรวม charge ; Dr `diff_under_code` = −diff ; ยอดติดลบของวันกลับฝั่ง |
| capitation settle/diff | สมุดทั่วไป วันสิ้นเดือน | Cr ลูกหนี้ / Dr `clear_code` และ `clear_short_code` ของชุด |
| fwf settle | สมุดทั่วไป วันสิ้นเดือน | Cr .501/.502 / Dr 2103010103.502 |
| stm/manual settle, diff | สมุดเงินรับ ตามวันที่โอน/ใบเสร็จ | Dr เงินฝาก (ต้องรู้รหัสบัญชีเงินฝาก) ; Cr ลูกหนี้ `RefID1` = งวด STM/เลขใบเสร็จ ; diff ตาม `diff_under/over_code` หรือ 3102010102.102 เมื่อเป็นหนี้ปีงบก่อน [อนุมาน] |
| ar_transfer (transfer) | สมุดเงินรับ | Dr เงินฝาก `RefID1` = ref_doc_no ; Cr `account_code` |

ช่องที่ยังขาด: รหัสบัญชีเงินฝากต่อแหล่งเงิน, การแปลง .203 → .20301 (และรหัส Manual อื่น), IP CR .217, เลขที่อ้างอิงธนาคาร, เลขที่เอกสาร/ใบเสร็จของการรับเงิน, กติกาส่วนต่างหนี้ปีก่อน

## 8. คำถามที่ต้องถามการเงิน

1. ยอดสมุดขายรายวันมาจากโปรแกรม Claim ใช่ไหม นำเข้าด้วยวิธีไหน (Excel → ImportData?) และอยากได้ไฟล์รูปแบบใด
2. .201 รายวันของ GL ต่ำกว่าของเรา (5 ต.ค. ต่าง 18,248) Claim ตัดอะไรออก ; ตั้งหนี้ IP ใช้วันที่อะไร
3. ใช้ .20301 แทน .203 ทั้งปีงบ 2570 หรือไม่ มีรหัส Manual อื่นที่ต้องแปลงไหม
4. STM/เงินโอนของหนี้ปีงบก่อน ลงส่วนต่าง 3102010102.102 ทุกกรณีหรือไม่ ; เงินงบปีก่อน (.201 ของ 3102010102) ต่างจาก .214 อย่างไร
5. รับเงินต้องอ้างเลขอะไรใน RefID1 และแยกบัญชีเงินฝากตามแหล่งเงินอย่างไร
6. ต้องการส่งรายวันหรือเดือนละครั้ง และใครเป็นคนสร้างหัวใบสำคัญ
