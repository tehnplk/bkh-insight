# โปรแกรม GL ของโรงพยาบาล (GL_HOS .accdb)

ศึกษาจาก 2 ไฟล์ ตรวจ 25 พ.ย. 2569: GL_HOS_70 (ปีงบ 2570 = 1 ต.ค. 2569–30 ก.ย. 2570 ข้อมูลถึง 6 พ.ย. 2569) และไฟล์ปีงบ 2569 (ข้อมูล ต.ค. 2568–ก.พ. 2569) schema ของ `DataTbl`/`DataTbl1`/`DataTbl2` และ index เหมือนกันทุกคอลัมน์ ต่างแค่ตารางสำรอง/รายงาน (ปี 70 เพิ่ม `Vertbl`, `SetTbl.FYear`, `ChartOfAccounts.TradingOri`, query `งบหน่วยงานส่งออก` ; ปี 69 มี `ChartOfAccount65` และตาราง "ข้อผิดพลาดในการวาง" ของ Access) ระดับความเชื่อมั่น: **[ไฟล์]** = อ่านจากข้อมูลจริงในไฟล์, **[เทียบ]** = เทียบกับ insight ด้วย db-cli, **[อนุมาน]** = ยังต้องถามการเงิน

schema เต็ม, saved query ที่เกี่ยวข้อง และผลเทียบเป็นตัวเลขอยู่ใน `references/schema.md`

## 1. อ่านไฟล์อย่างปลอดภัย

- คัดลอกไฟล์ไปที่ scratchpad ก่อนเสมอ อ่านจากสำเนา ห้ามเปิดด้วย Access หรือ COM (`Access.Application`) เพราะ macro/VBA รันเองได้
- อ่านด้วย OLE DB: PowerShell `System.Data.OleDb` provider `Microsoft.ACE.OLEDB.16.0` (หรือ 12.0) connection string มี `Mode=Read` ใช้ `GetOleDbSchemaTable` (Tables/Columns/Primary_Keys/Foreign_Keys/Views/Procedures) ได้ทั้งรายการตาราง คอลัมน์ ความสัมพันธ์ และ SQL ของ saved query ; อ่านแค่ SELECT
- อ่านไม่ได้ผ่าน OLE DB: `MSysObjects` (no read permission จึงไม่เห็น linked table), form, report, VBA, macro (ฟังก์ชันใน query เช่น `getFD()`, `NetToDr()`, `GetGFType()` อยู่ใน VBA)
- `LIKE` ผ่าน OLE DB ใช้ `%`/`_` ไม่ใช่ `*` ; คำว่า `note`/`lines` ใช้เป็น alias ไม่ได้ (reserved)
- ข้อมูลบุคคลในไฟล์: `SetTbl` (ชื่อผู้บริหาร/ผู้ทำบัญชี), `Vertbl` (ชื่อผู้เขียนโปรแกรม), `DataTbl.Note` (ข้อความอิสระ อาจมีชื่อผู้ขาย/บุคคล/เลขบัญชี), `DataTbl1.RefID1` ของบัญชี .307/.602/.603/1102050102.106/.107 (ชื่อผู้ป่วย) ถ้าจะดูค่าให้แสดงเป็นรูปแบบ (9 = ตัวเลข, T = คำไทย) หรือนับเท่านั้น, ชื่อบัญชีเงินฝากมีเลขบัญชีธนาคาร ห้ามคัดลอกค่าเหล่านี้ ; ไม่พบตารางผู้ใช้/รหัสผ่าน

## 2. โครงสร้าง [ไฟล์]

โปรแกรม "HOS Previous > 2013+" เมนู 5 ขั้น: ตั้งค่าเริ่มต้น (`SetTbl`) → ผังบัญชีย่อยสุด → ชื่อบัญชีหลักในงบ (`AccID1`) → ลงข้อมูล (form `DataTbl`) → รายงาน (form `Form1`)

- **ใบสำคัญ** = `DataTbl` (header, PK `ID` autonumber) + `DataTbl1` (บรรทัด, FK `ID`) ; `DataTbl2` เป็นแบบแบน header+บรรทัดในแถวเดียว (ว่าง) รวมกันใน query `UnionData` ที่รายงานทุกตัวอ่าน
  - `DataTbl`: `AccDate` วันที่บัญชี, `DataDate` วันที่คีย์, `DocID` เลขที่เอกสาร (ข้อความ), `BookID` → `BookTbl`, `BudgetType` → `BudgetTypeTbl`, `Note` คำอธิบาย, `ApAr` รายการย่อย/บัญชีย่อยลูกหนี้-เจ้าหนี้ → `SubLedTbl` (ไม่ได้ใช้ ว่างทุกแถว), `OrgID1` หน่วยงาน (`00` = รพ. เอง), `ChargeID`/`ChargeDate`/`RefID` (ว่าง), `IsClosing`, `ToBe0`, `NotGF3`
  - `DataTbl1`: `AccCode1` → `ChartOfAccounts.AccCode`, `Dr`, `Cr` (Currency 4 ตำแหน่ง), `RefID1` อ้างอิงบรรทัด (ข้อความ 50), `RefDate` (ว่าง), `InterTransac`, `RunID1`/`RunID2` ลำดับบรรทัด
  - บรรทัดหนึ่งมี Dr หรือ Cr ฝั่งเดียว บัญชีเดียวกันซ้ำได้หลายบรรทัดในใบเดียว ; โปรแกรม**ไม่บังคับ Dr = Cr** (พบใบที่ยังไม่สมดุล 4 ใบ มี query `NCheckDrCr` ไว้ตรวจ) ไฟล์ที่เราส่งต้องสมดุลเอง
- **สมุดรายวัน** (`BookTbl`): 1 เงินรับ (ร.), 2 เงินจ่าย (จ.), 3 ขาย (ข.), 4 ซื้อ (ซ.), 5 ทั่วไป (ท.) ; เลขที่เอกสาร `รร.<n>/70` (รับ), `รจ.<n>/70` (จ่าย), `รท.<n>/70` ตามปีงบ 2 หลัก ; สมุดขาย/ซื้อไม่มีเลขที่เอกสาร
- **ประเภทเงิน** (`BudgetTypeTbl`): 1 เงินงบประมาณ (ไม่ส่ง GF), 4 เงินบำรุง (รายการลูกหนี้ทั้งหมด), 9 ประกันสังคม, 10 สวัสดิการ, 11 อื่นๆ, 12 บัญชี๕, 13 บัญชี๗
- **ยอดยกมา**: ใบ `ID` 1 (เงินบำรุง) และ 2 (งบประมาณ) ลงวันที่ 30 ก.ย. ของปีก่อน `SetTbl.StartDate` ; ช่วงรายงานคือ `SetTbl.FDate`/`TDate` ปีงบ `FYear` เป็นเลขไทย
- **ผังบัญชี** `ChartOfAccounts` (928 รหัส): รหัส `##########.###` (10.3) เหมือนของเรา มีรหัสย่อย 5 หลัก `.xxx01` "ภายในกรมเดียวกัน (Manual)" เพิ่มปี 2569 (เช่น .20301, .50601) ; `MinorID` บัญชีคุม (`AccID1`) → หมวดในงบ (`AccIDTbl`) ; `GFId` = 10 หลักแรก (รหัส GFMIS, ตาราง `GF`/`GFAndGL`) ; `Trading` รหัสคู่ค้า GFMIS (80074 สปสช., 80066 สปส., 03004 กรมบัญชีกลาง, 21002 แรงงานต่างด้าว) ; `UseOrNot` Use/No ; `NotGF1` ไม่ส่ง GF
- ไม่มีคอลัมน์ VN/AN/HN ในตารางใดเลย ระบบรายตัวมีแค่ 2 ช่อง ดูข้อ 4.1

## 3. บัญชีลูกหนี้ของเราใน GL [ไฟล์]

ทุกรหัสใน `ar_account` (code/revenue/diff/clear) และ `ar_transfer.account_code` ของเรามีใน `ChartOfAccounts` ครบ 166/166 รหัส (ตรวจ 25 พ.ย. 2569) ; ที่ GL ตั้ง `UseOrNot = No`: 1102050101.223/.224, 1102050194.115/.116, 4301020105.267/.268/.269 ข้อต่าง:

- **การเงินใช้รหัส Manual แทนรหัสหลักบางตัว**: UC OP นอก CUP ในจังหวัด สธ. ลง **1102050101.20301** / รายได้ 4301020105.20301 (ไม่ใช่ .203) ; ยกมามี .50601, .70201, .70401 ; `ar_account` ของเรามีรหัสเหล่านี้แล้ว แต่กติกาบัญชี (`ar_account_rule`) ยังลง .203 ต้องตกลงกับการเงินว่าจะแก้กติกาหรือแปลงตอนส่งออก
- เงินฝากธนาคารแยกหลายบัญชีย่อย เงินโอนจาก สปสช. เข้า 1101030102.10105 ("รับโอน UC") ส่วนเงินสดห้องเก็บเงิน 1101010101.101 ; ของเราไม่ระบุรหัสเงินฝาก (`CASH_NAME` code null ใน `journal.ts`)

## 4. การเงินลงลูกหนี้ใน GL อย่างไร (ต.ค. 2569) [ไฟล์]

1. **ตั้งหนี้รายวัน = สมุดขาย (BookID 3)** หนึ่งใบต่อวัน `Note` "บันทึกบัญชีลูกหนี้ค่ารักษาพยาบาลประจำวัน" `DocID` NULL ไม่มี RefID **คีย์ทั้งเดือนในวันเดียวหลังสิ้นเดือน** (`DataDate` เดียวต่อเดือน: ต.ค. 68 → 8 พ.ย. 68, พ.ย. → 4 ธ.ค., ธ.ค. → 8 ม.ค., ม.ค. → 7 ก.พ., ต.ค. 69 → 7 พ.ย. 69) ID ของใบเรียงตามวันที่ ; ใบสมุดซื้อ (BookID 4) คีย์วันเดียวกันแบบเดียวกัน ; บรรทัดละบัญชีต่อวัน:
   - Dr ลูกหนี้ = **ยอดสุทธิหลังเพดาน/สัดส่วน** (ค่ารักษา − ส่วนต่าง)
   - Cr รายได้คู่ = ค่ารักษาเต็ม
   - Dr บัญชีส่วนต่าง (4301020105.239 แยกบรรทัดต่อบัญชีลูกหนี้, 4301020106.315/.317 ประกันสังคม)
   - มีบรรทัดยอด 0 ติดมาจากแม่แบบ (query `DelDataTbl100` ลบบรรทัด 0/0)
   - IP ลง .202 และแยก CR เป็น .217 แล้ว (ของเรายังรวมใน .202)
   - **ใครเขียน**: โปรแกรม Claim **ไม่ได้เขียน GL แล้ว** (ผู้ใช้ยืนยัน: ตัวเชื่อม Access ODBC มีปัญหากับรุ่น Office) ตาราง staging ของ Claim (`ac_acchead`/`ac_accdetail` ใน claimx) มีแค่ 4 ใบ ล่าสุด ก.ค. 2566 และเป็นใบ**รายเดือน** `accdesc` "รายงานสรุปลูกหนี้ค่ารักษาพยาบาล AAA" ลงวันสิ้นเดือน (bookid 5 แล้ว 3) ไม่ใช่ใบรายวันแบบปัจจุบัน ; `conf.ini` ของ Claim มีหมวด `[GL_CONNECTION]`/`[GL_PROFILES]` (`GL=0`)
   - ใบรายวันปัจจุบันการเงินนำเข้าเองผ่านตาราง `TB1` (ผู้ใช้ยืนยันจากหน้าจอ ดูข้อ 6) ลำดับ `RunID2` (autonumber ของบรรทัด) มี 2 แบบ: **ปีงบ 69 (ต.ค. 68–ม.ค. 69)** บรรทัดเข้าทีละใบ (เปลี่ยนใบ 32–38 ครั้งต่อเดือน) เรียงเป็นคู่ ลูกหนี้ Dr → รายได้ Cr → ส่วนต่าง Dr = ตรงกับการนำเข้าทีละใบผ่าน TB1 ; **ต.ค. 69** (ยังไม่รู้ว่าทำวิธีไหน) บรรทัดเข้าทีละบัญชีวนทุกวัน (เปลี่ยนใบ 1,009 ครั้งจาก 1,031 บรรทัด, บัญชีเรียงจากน้อยไปมาก) = วางต่อท้ายตาราง `DataTbl1` จากแผ่นงานที่มีคอลัมน์ ID ของใบและเรียงตามรหัสบัญชี ; ไฟล์ปี 69 มีตาราง "ข้อผิดพลาดในการวาง" 3 แถว (Access สร้างเมื่อวางข้อมูลไม่ผ่าน) เป็นหลักฐานว่ามีการวางจาก Excel
   - เดือนละ 30–31 ใบ บรรทัด 941–1,031 ต่อเดือน บรรทัดยอด 0 เหลือ 22–151 ต่อเดือน
2. **ปรับปรุงสิ้นเดือน = สมุดทั่วไป (BookID 5)** ใบเดียววันสิ้นเดือน (ทำทุกเดือน ต.ค. 68–ม.ค. 69 และ ต.ค. 69 คีย์ 6–10 วันหลังสิ้นเดือน) ; เดือนที่ไม่มีเงินโอนเหมาจ่ายเข้า (พ.ย./ธ.ค. 68) Dr .229 เต็มยอด .201 ; "ปรับปรุงบัญชีลูกหนี้ตามนโยบายบัญชีสิ้นเดือน": Cr .201 ทั้งเดือน / Dr .214 = เงินโอนเหมาจ่ายที่รับในเดือน / Dr .229 ส่วนที่เหลือ ; Cr .209 / Dr .217 ; Cr .701 / Dr 4301020106.711 ; Cr .501 / Dr 2103010103.502 (+ โอนระหว่างบัญชีเงินฝาก) = ตรงกับกติกา `/fund/ar-capitation` และ fwf ของเรา
3. **รับเงิน = สมุดเงินรับ (BookID 1)** ใบละวันโอน "รับเงินโอนค่าบริการทางการแพทย์ - สปสช." หลายสิบบรรทัด: Dr เงินฝาก `RefID1` = เลขอ้างอิงธนาคาร/ลำดับ (`<เลข>/<ลำดับ>`) ตามด้วย Cr ลูกหนี้/รายได้ที่ `RefID1` = งวด STM (`YYMM_OP_NN`, `YYMM_OP_NN_อุทธรณ์`), เลขที่ REP/หนังสือ (9 หลัก) หรือชื่อโครงการ ; ส่วนต่างของหนี้ปีก่อนลง 3102010102.102 (ผลสะสมจากการแก้ไขข้อผิดพลาด-รายได้) ; เงินงบปีก่อนลง 3102010102.201 (บางรายการการเงินลง .214) ; ผู้ป่วยใน UC (.202) รับเป็น**ก้อนเดียวต่อเดือนไม่มีอ้างอิง** (ปี 69: ก.พ. 69 Cr .202 8,084,848.27 = ยอดตั้งหนี้ ธ.ค. 68 พอดี) .401/.402 บางเดือนก้อนเดียว บางเดือนละ REP

### 4.1 ตัดลูกหนี้รายตัวมีหรือไม่ (ตรวจซ้ำ 25 พ.ย. 2569) [ไฟล์]

**ไม่มีทะเบียนลูกหนี้รายราย (VN/AN/HN)** ตั้งหนี้เป็นยอดรวมรายวันไม่มีอ้างอิง แต่ฝั่งรับเงินบางบัญชีลงบรรทัดละราย/ละเอกสารใน `RefID1`:

- **รายบุคคล (ชื่อผู้ป่วยใน RefID1)**: กองทุนทดแทน .307 (71 บรรทัดในใบรับเงินใบเดียว), พรบ.รถ 1102050102.602/.603 (43 บรรทัด), ชำระเงิน 1102050102.106/.107 ; ค่าเป็นคำนำหน้า + ชื่อ สกุล ทุกบรรทัด ไม่มี HN ; ไม่มีหนี้ฝั่ง Dr ที่อ้างชื่อเดียวกัน จึง**ไม่ได้จับคู่ open item** (บัญชี × RefID1 ที่มีทั้ง Dr และ Cr = 0 คู่) เป็นแค่รายละเอียดของการรับเงิน
- **รายเลข REP**: เบิกจ่ายตรง .401/.402, อปท. 1102050102.801–.803, .110 ใช้เลข 9 หลัก `YYMM#####` (8 หลัก 1 แถว) ; 54 จาก 86 เลขตรงกับ `stm_summary.rep_no` ใน insight เฉลี่ย 21 รายต่อ REP (1–67) = ตัดระดับ REP ไม่ใช่รายราย
- **ระดับงวด/โครงการ**: UC .216/.20301 อ้างงวด STM หรือชื่อโครงการ ; .201/.202/.209/.301/.302 ไม่มีอ้างอิง
- ฟีเจอร์บัญชีย่อยของโปรแกรม (`DataTbl.ApAr` → `SubLedTbl`, report `บัญชีย่อยตามรายชื่อ*`, `บัญชีย่อยตามบัญชี`, query `qrySubLedger1–6`, `N00000AR` ตรวจ ref ที่ปิดแล้ว, ตาราง `DebtData`) **มีโครงสร้างแต่ไม่ได้ใช้**: ApAr ว่างทุกใบทุกเดือนทุกสมุด, SubLedTbl/DebtData 0 แถว ; ผังตั้ง `SubLedgerReport = Yes` ไว้ 56 จาก 86 บัญชีลูกหนี้
- ไฟล์ปีงบ 69 เหมือนกัน: ApAr ว่างทุกใบ ต.ค. 68–ก.พ. 69, SubLedTbl/DebtData 0 แถว

## 6. ช่องทางนำเข้าในโปรแกรมและ spec การเขียน [ไฟล์]

เป้าหมาย: ระบบเราสร้างไฟล์ให้การเงินนำเข้าผ่านโปรแกรม GL เอง (Access เป็นผู้เขียน ไม่ต้องใช้ตัวเชื่อม ODBC) ไม่มีตาราง staging สำหรับใบทั้งใบ

**ช่องที่การเงินใช้จริง = ตาราง `TB1` (ผู้ใช้ยืนยันจาก Form2 ใน Access, 25 พ.ย. 2569)** ขั้นตอนตามข้อความกำกับใน Form2:
1. กดปุ่ม "ดึงข้อมูลงบทดลองเข้า" แล้วตอบ OK ทุกครั้ง ชื่อ field ต้องเป็น `AccCode1, AccName1, Dr1, Cr1` ชื่อตารางต้องเป็น `TB1`
2. กดปุ่ม "ตรวจสอบงบก่อนการนำเข้า" (query `TB1 Without Matching ChartOfAccounts` = แถวที่รหัสไม่อยู่ในผัง) ใช้แค่รหัสบัญชี เดบิตงวดนี้ เครดิตงวดนี้ ; ชื่อบัญชีว่าง = รหัสไม่มีในผัง ต้องเปลี่ยนเป็นรหัสที่มี ไม่งั้นบรรทัดนั้นไม่เข้า (FK ของ `DataTbl1.AccCode1`)
3. เปิดหน้า "ลงบัญชี" (form `DataTbl`) เติมหัวใบ แล้วกดปุ่มนำเข้า (`Command140` รัน `DoCmd.OpenQuery "qryForAddData1"` อย่างเดียว ไม่ล้าง TB1 ; ผู้ใช้ยืนยันจาก VBA) = `qryForAddData1`: `INSERT INTO DataTbl1 (ID, AccCode1, Dr, Cr) SELECT forms!DataTbl!ID AS AA, TB1.acccode1, TB1.dr1, TB1.cr1 FROM TB1` ; `dr1`/`cr1` ที่ว่างเข้าใบเป็น NULL จึงต้องใส่ 0 ฝั่งที่ไม่มียอด

ปุ่ม "ดึงข้อมูลงบทดลองเข้า" เป็น macro `RunMenuCommand` Command = `Import` (เมนู Get External Data แบบเก่า) ซึ่ง Access 2007 ขึ้นไปไม่มี กดแล้วขึ้น "You tried to perform an operation involving a function or feature that was not installed in this version of Microsoft Access" ; **วิธีแก้ที่ผู้ใช้ทดสอบแล้ว**: เปลี่ยน Command เป็น `ImportAttachExcel` แล้วในตัวช่วยนำเข้าเลือก "Append a copy of the records to the table" = `TB1` ; ไฟล์ GL ปีอื่นที่ยังเป็น `Import` ต้องแก้แบบเดียวกัน หรือใช้เมนู External Data › New Data Source › From File › Excel แทน

**TB1 ไม่ถูกล้างโดย query หรือปุ่มนำเข้า**: `qryForAddData1` เป็น INSERT อย่างเดียว ปุ่ม `Command140` ก็ไม่ล้าง และไม่มี saved query ใดลบ TB1 (DELETE ที่มีคือ `DelDataTbl100` ลบบรรทัด 0/0 ของ DataTbl1 และ `Qry_Restart` ลบ DataTbl) ; ไฟล์ปี 69 และ 70 มี TB1 0 แถว แปลว่าถูกล้างทางอื่น (VBA ที่อ่านไม่ได้หรือลบมือ) ไม่รู้แน่ชัด → **ก่อนนำเข้าแต่ละใบต้องให้การเงินลบแถวใน TB1 ให้ว่างเอง** ไม่งั้นแถวเก่าจะเข้าใบซ้ำ

`TB1` (ผู้ใช้เปิด Design View ยืนยัน 25 พ.ย. 2569): `ID` AutoNumber (Long Integer, Increment, Indexed Yes No Duplicates, PK), `acccode1`/`accname1` Short Text, `dr1`/`cr1` Number (Double) ; ไฟล์ Excel จึงต้องไม่มีคอลัมน์ ID (Access เติมให้) และ `dr1`/`cr1` ฝั่งที่ไม่มียอดต้องเป็น 0 ไม่ใช่ช่องว่าง (ว่าง = NULL เข้า DataTbl1)

ช่องอื่นที่มีในไฟล์แต่การเงินไม่ได้ใช้: `AppImportData` (ตาราง `ImportData(Code, Dr, Cr)` ไม่มีในไฟล์), วางต่อท้าย `DataTbl1` ตรง, import spec ข้อความความกว้างคงที่ (`MSysIMEXSpecs` spec 1: รหัสบัญชี 1–15, ชื่อบัญชี 16–88, เดบิต/เครดิต/สุทธิ 89–124 ตั้ง Skip) ซึ่งเป็นของรุ่นเก่า
- ส่งออก: query `งบหน่วยงานส่งออก` (รหัสบัญชี, ชื่อ, ยอดยกมา, เดบิต, เครดิต, ยอดยกไป), `AppOrg*`/`AppSub*` เขียนลงไฟล์ mdb ภายนอก

**กติกาของตาราง (ต้องเติมให้ถูกเมื่อสร้างไฟล์หรือสคริปต์)**
- `DataTbl.ID` AutoNumber (PK) ; `DataTbl1.RunID2` AutoNumber (ลำดับบรรทัด ไม่มี PK ในตารางบรรทัด) ; บรรทัดผูกหัวใบด้วย `DataTbl1.ID` (FK, cascade update/delete)
- ต้องมีค่า: `DataTbl.AccDate`, `DataTbl.OrgID1` (`'00'`), `DataTbl1.AccCode1` (ต้องมีใน `ChartOfAccounts`, FK), `Dr`/`Cr` (Currency, ค่าเริ่มต้น 0, **validation `>= 0`** จึงห้ามส่งค่าติดลบ ยอดติดลบให้กลับฝั่ง)

## 7. แนวทางส่งข้อมูลจากระบบเรา (ข้อเสนอ ยังไม่ทำ)

ระดับรายละเอียด: **ยอดรวมต่อบัญชีต่อวันต่อสมุด** ไม่ส่งรายราย

**ไฟล์ที่ระบบเราสร้าง**: Excel **ใบละใบสำคัญ** หัวคอลัมน์ `AccCode1 | AccName1 | Dr1 | Cr1` (ตรง TB1) แจ้งหัวใบให้การเงินคีย์ (วันที่, สมุด 3, ประเภทเงิน 4, คำอธิบาย) ; กติกา: Dr1/Cr1 ไม่ติดลบ ปัด 2 ตำแหน่ง, ไม่มีบรรทัดยอด 0, Dr รวม = Cr รวม, รหัสบัญชีต้องมีในผังของไฟล์ GL ปีนั้น, AccName1 ใส่ชื่อตามผัง (ช่วยให้ตรวจเห็นรหัสที่ไม่มี) ; เรียงบรรทัดเป็นคู่ ลูกหนี้ Dr → รายได้ Cr → ส่วนต่าง Dr แบบใบปี 69 ; ใส่ยอดรวมและเลขชุดในชื่อไฟล์ให้การเงินตรวจซ้ำได้ ; TB1 ต้องว่างก่อนนำเข้าทุกใบ

**ยังไม่ได้ตัดสิน**: ไฟล์ละใบ (ใบละวัน 30–31 ไฟล์ต่อเดือน) หรือไฟล์เดียวทั้งเดือนหลายชีต ; ทั้งสองแบบยังต้องนำเข้าทีละใบเพราะ `qryForAddData1` เติมเข้าใบที่เปิดอยู่ใบเดียว

| ar_ledger | ใบใน GL | บรรทัด |
|---|---|---|
| set/adjust/cancel/reverse + diff ของ source หนี้ (rcpt_debt, ipt) | สมุดขาย ใบละ `entry_date` | Dr ลูกหนี้ = ผลรวม charge + diff ; Cr `revenue_code` = ผลรวม charge ; Dr `diff_under_code` = −diff ; ยอดติดลบของวันกลับฝั่ง |
| capitation settle/diff | สมุดทั่วไป วันสิ้นเดือน | Cr ลูกหนี้ / Dr `clear_code` และ `clear_short_code` ของชุด |
| fwf settle | สมุดทั่วไป วันสิ้นเดือน | Cr .501/.502 / Dr 2103010103.502 |
| stm/manual settle, diff | สมุดเงินรับ ตามวันที่โอน/ใบเสร็จ | Dr เงินฝาก (ต้องรู้รหัสบัญชีเงินฝาก) ; Cr ลูกหนี้ `RefID1` = งวด STM/เลขใบเสร็จ ; diff ตาม `diff_under/over_code` หรือ 3102010102.102 เมื่อเป็นหนี้ปีงบก่อน [อนุมาน] |
| ar_transfer (transfer) | สมุดเงินรับ | Dr เงินฝาก `RefID1` = ref_doc_no ; Cr `account_code` |

ช่องที่ยังขาด: รหัสบัญชีเงินฝากต่อแหล่งเงิน, การแปลง .203 → .20301 (และรหัส Manual อื่น), IP CR .217, เลขที่อ้างอิงธนาคาร, เลขที่เอกสาร/ใบเสร็จของการรับเงิน, กติกาส่วนต่างหนี้ปีก่อน

## 8. คำถามที่ต้องถามการเงิน
